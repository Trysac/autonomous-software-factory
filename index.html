How it works

Eight steps, two of them human.

The models write and correct code; deterministic code decides what is accepted. Nothing reaches a repository without passing the gates a senior team would demand.

Approve

A human selects and approves each specification before anything is built.

Plan and budget

Every item is estimated against a monthly budget with a worst-case reservation.

Generate

Code, tests and documentation are generated in batch, overnight, at the lowest price tier.

Quality gates

Lint, format, types, tests and coverage, docs standard, secret scan and dependency audit.

Correct

A bounded correction loop fixes failing gates with file-level tools only, never a shell.

Independent audit

A separate read-only reviewer checks the result against its specification.

Publish

One clean, squashed commit per pull request; the factory never pushes to main.

Review

A human reviews and merges. CI re-runs the gates on Linux and Windows.

The twelve roles behind the steps models with narrow permissions, and deterministic code
  • Analyst (model): turns an idea into a specification with testable acceptance criteria.
  • Architect (model): splits a large system into modules with frozen interfaces.
  • Generator (model): writes the code, tests and documentation of one item in one batch request.
  • Fixer (model): repairs failing gates in bounded rounds, with file tools only.
  • Auditor (model): a read-only reviewer, separate from the author, that checks against the spec.
  • Docs writer (model): rewrites the documentation to match the code actually delivered.
  • Security engineer (model): Semgrep, OSV-Scanner and a STRIDE review where there is auth or user data.
  • Visual QA (model): screenshots web apps at two widths and checks contrast; evidence, never a gate.
  • Planner (deterministic): estimates each item and reserves its worst case against the budget.
  • Quality and security gates (deterministic): the checks every pull request must pass.
  • Publisher and release manager (deterministic): one pull request per item; tags only after a human merge.
  • Maintenance (deterministic): merges only patch dependency updates whose CI passed.

Notes

Gemini generates almost for free, so its cost sits in correction. On 19 projects its low-cost correction model could not close defects of a few lines; they were finished by hand, and each hand fix is recorded as an intervention (this page said 84 by the pipeline alone before later fixes were recorded). Gemini's audit was also far cheaper and reported fewer findings, which reads as a less demanding reviewer rather than better code.

DeepSeek runs only in its off-peak price window, at half price, and is the cheapest line so far: it finished all 100 projects, 96 with no human fix. Line D puts code quality before cost: generation runs on a stronger model, which shows in larger projects, and most of its spend goes to correction. Line D is paused after 23 projects; its figures cover those, including early infrastructure problems fixed the same day (stalled connections and a per-project budget set too low).

All times use one definition: the median from submission to the model until the pull request opens, recomputed from the ledger. Earlier figures on this page were computed differently and are replaced.

Lines for OpenRouter and two self-hosted lines (a rented cloud GPU and a local laptop GPU) are built on the same pipeline and gates and have not run yet. Confidential client projects are routed only to providers that do not train on inputs and offer zero data retention, and every dependency is checked against a license profile.
